# Mentor–Mentee Allocation Pipeline

A set of Python scripts that matches mentees to mentors based on project preferences, SOP scores, and mentor capacity.

---

## Folder Structure

```
project/
├── topics.csv
├── mentor.csv
├── mentee_preferences_detailed.csv        ← only mentee input you need to provide
└── scripts/
    ├── filter_mentees.py
    ├── allocator.py
    ├── analyze_and_fix.py
    ├── allocation_algorithm.py
    └── run_capacity_10.py
```

---

## Input File Formats

### `topics.csv`

No header row. One topic per line: code, then name.

```
AB12, Machine Learning
CS101, Data Structures and Algorithms
ML203, Computer Vision
DS301, Database Systems
```

**Rules:**
- Code must be 1–3 letters followed by 2–3 digits (e.g. `CS101`, `AB12`, `ML23`)
- Everything after the first comma is treated as the topic name
- No header row

---

### `mentor.csv`

One row per mentor.

```
Full Name, Project Codes, Current Year at IIT Bombay (as of April 2025)
Alice Smith, CS101;ML203;AB12, PhD
Bob Jones, DS301;CS101, Postdoc
Carol White, , 5th year
```

| Column | Required | Notes |
|--------|----------|-------|
| `Full Name` | Yes | Exact header name |
| `Project Codes` | Yes | Semicolon-separated topic codes matching `topics.csv`; can be blank — `analyze_and_fix.py` fills these in |
| `Current Year at IIT Bombay (as of April 2025)` | Yes | Drives seniority ranking in allocation priority |

**Accepted year values** (in descending seniority):
`Postdoc` → `PhD` → `Alumni` → `5th year` → `4th year` → `3rd year` → `2nd year` → `1st year`

---

### `mentee_preferences_detailed.csv`

**This is the only mentee input file you need to provide.**
Long format — one row per preference per mentee. A mentee with 3 preferences has 3 rows.

```
Mentee Roll No, Mentee Name, Preference Number, Specific Category, SOP Score, Year
21B0001, Jane Doe, 1, CS101, 7.5, Third year
21B0001, Jane Doe, 2, ML203, 7.5, Third year
21B0001, Jane Doe, 3, AB12, 7.5, Third year
21B0002, John Smith, 1, DS301, 6.0, Second year
21B0002, John Smith, 2, CS101, 6.0, Second year
```

| Column | Required | Notes |
|--------|----------|-------|
| `Mentee Roll No` | Yes | Unique identifier per student; used to group rows for the same mentee |
| `Mentee Name` | Yes | Full name |
| `Preference Number` | Yes | Integer 1–5, where 1 is the most preferred |
| `Specific Category` | Yes | A topic code from `topics.csv` |
| `SOP Score` | Yes | Numeric, 0.0 to 10.0; only needs to appear once per mentee — later rows for the same mentee can leave it blank |
| `Year` | Yes | Year of study (e.g. `Third year`, `Second year`); only needs to appear once per mentee |

## Output Files

| File | Generated by | Description |
|------|-------------|-------------|
| `mentee_preferences_detailed.csv` | `filter_mentees.py` | Cleaned in place — mentees without SOP scores removed |
| `mentor-project-code.csv` | `allocator.py` | Mentor names mapped to their project codes |
| `mentee.csv` | `allocator.py` | Auto-generated wide-format mentee file (one row per mentee) |
| `mentee-preferences-cleaned.csv` | `allocator.py` | Mentee preferences with invalid codes blanked out |
| `allocations.csv` | `allocator.py` | Simple allocation output |
| `allocations_capacity10.csv` | `run_capacity_10.py` | **Final allocations** — main output |
| `allocations_capacity10_stats.txt` | `run_capacity_10.py` | Summary statistics (assigned %, preference rank distribution) |
| `allocations_capacity10_mentor_loads.csv` | `run_capacity_10.py` | Per-mentor assignment counts |
| `allocations_unassigned_capacity10.csv` | `run_capacity_10.py` | Mentees who could not be placed, with reasons |

## Steps to Run

All commands are run from inside the `scripts/` directory.

```bash
cd project/scripts
```

### Step 1 — Filter mentees with no SOP score

Removes any mentee (all their rows) who has no valid SOP Score. Overwrites the input file in place.

```bash
python3 filter_mentees.py \
  --input ../mentee_preferences_detailed.csv \
  --output ../mentee_preferences_detailed.csv
```

Prints a summary of how many mentees were kept and dropped, with names of those dropped.

---

### Step 2 — Build mentor codes and run basic allocation

Reads `topics.csv`, `mentor.csv`, and `mentee_preferences_detailed.csv`.
Auto-generates `mentee.csv`. Produces `allocations.csv` as a simple first-pass allocation.

```bash
python3 allocator.py
```

---

### Step 3 — Fix mentors with missing project codes

Reads `mentor-project-code.csv` (produced in Step 2) and overwrites it in place,
assigning codes to any mentor who had none, based on the most-requested topic codes.

```bash
python3 analyze_and_fix.py
```

---

### Step 4 — Run the full allocation

Runs the main allocation algorithm with `mentor_capacity=10` and `max_codes_per_mentor=4`.
Reads `mentee_preferences_detailed.csv` and `mentor.csv` directly.

```bash
python3 run_capacity_10.py
```

**The primary output is `allocations_capacity10.csv`.**
Check `allocations_unassigned_capacity10.csv` for mentees who could not be placed and why.

---

## Allocation Logic Summary

- Mentees are prioritised by **SOP score** (highest first), then **year of study** (senior first)
- Each mentee is matched to their highest available preference where capacity remains
- Each mentor can take up to **10 mentees** across up to **4 topic codes**
- Unassigned mentees are logged with one of these reasons:
  - `no preferences listed`
  - `no mentor offers preferred codes`
  - `capacity full for preferred codes`
  - `other (matching constraints)`
